The real `ArchiveFileService.java:6251` deletes the physical file before removing the database entity at line 6275. If the database operation or transaction commit subsequently fails, the original row can remain while its file is gone. `restoreDocumentFromBin()` only restores metadata and tolerates preview-generation failures, so `undo()` can then permanently delete the staged replacement and report an ordinary failure. **Suggested fix:** retain the staged document whenever permanent deletion has an uncertain outcome. Verify the original’s content before allowing cleanup, or implement recovery that also handles filesystem effects on the server.
