1. **[P2] Failed replacement permanently changes the original’s automatic tags.** `DocumentReplacement.java:889` and `DocumentReplacement.java:898`. Renaming the original to `Ersetzt_…` invokes automatic tagging. Renaming it back does not remove tags introduced by that temporary name. For example, with the existing test’s rule “name is not Brief.pdf → Sonstiges”, a failure renaming the replacement leaves the original named `Brief.pdf` but incorrectly tagged `Sonstiges`. The real server applies tags at `ArchiveFileService.java:2930` and adds matching tags without removing nonmatching ones. Existing tag values can also be overwritten. **Suggested fix:** preserve the original’s tags and values before its temporary rename, restore them during rollback, and report restoration failures. Extend `testRenamingTheNewDocumentFailsAndTheExistingOneGetsItsNameBack` with the negative naming rule and assertions on the original’s tags.

The PR says an already-renamed original gets its name back, while `testRenamingBothBackFails` explicitly verifies that it can retain `Ersetzt_…`. Say that restoring the name is attempted, the replacement is retained, and the resulting server state is reported.
