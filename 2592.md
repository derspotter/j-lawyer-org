1. **[P2] `j-lawyer-backupmgr/src/main/java/org/jlawyer/backupmgr/impl/SqlDumpUtils.java:823` — Ignoring SQL mode rejects valid trigger dumps and discards all replacements.** Backslashes always escape the following character. However, mysqldump restores a trigger’s saved SQL mode before emitting its original definition, which can include `NO_BACKSLASH_ESCAPES`. Under that mode, `SET NEW.a = '\'` is valid. The scanner consumes its closing quote as an escape and returns `-1`. The file wrapper consequently discards even earlier valid collation replacements, leaving the unsupported collation for restoration. I reproduced this with the branch’s scanner. See [mysqldump’s trigger writer](https://github.com/mysql/mysql-server/blob/8.0/client/mysqldump.cc#L3245) and [MySQL’s string-literal rules](https://dev.mysql.com/doc/refman/8.0/en/string-literals.html).

   **Suggested fix:** Track relevant SQL-mode changes and restoration, including executable `SET` comments, and apply the corresponding quoting rules. Add a trigger-dump regression containing a trailing backslash under `NO_BACKSLASH_ESCAPES`, verifying that actual collations are replaced and the trigger remains unchanged.
