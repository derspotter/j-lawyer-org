1. **[P2] `j-lawyer-backupmgr/src/main/java/org/jlawyer/backupmgr/impl/SqlDumpUtils.java:941` — Stored-program bodies incorrectly change the scanner’s session mode, causing silent literal corruption.** Every semicolon calls `endStatement()`, including those inside a `CREATE PROCEDURE` or compound trigger under `DELIMITER ;;`. Consequently, subsequent body-level `SET` statements reach `applySet()` at line 1064.

   I reproduced this with a procedure created under `sql_mode=''` containing:

   ```sql
   BEGIN
     SET @dummy = 1;
     SET sql_mode = 'NO_BACKSLASH_ESCAPES';
     SELECT 'it\'s COLLATE utf8mb4_0900_ai_ci',
            'it\'s COLLATE utf8mb4_0900_ai_ci';
   END
   ```

   With one preceding table collation, the new scanner returns **2 replacements instead of 1**, rewriting the first quoted literal. The positive count causes the file wrapper to accept the corrupted output. With only one escaped literal, it returns `-1` and discards all replacements. Both cases pass against `25b452efb`. A compound trigger assigning `NEW.sql_mode` reproduces the problem too.

   The body belongs to one stored-program definition and is not executed during creation. [MySQL documents this delimiter behavior](https://dev.mysql.com/doc/refman/8.0/en/stored-programs-defining.html).

   **Suggested fix:** Respect client statement delimiters and apply mode changes only to top-level session `SET` statements. Do not interpret column assignments as system-variable assignments. Add compound-trigger and procedure regressions covering both outcomes.
