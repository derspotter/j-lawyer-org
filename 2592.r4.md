2. **P1 — Quoted executable collations in INSERT statements survive successful preparation.** `SqlDumpUtils.java:980–1001`, `:1021–1024`

   ```sql
   CREATE TABLE t(a TEXT) COLLATE=utf8mb4_0900_ai_ci;
   INSERT INTO t VALUES ('a' COLLATE 'utf8mb4_0900_ai_ci');
   ```

   Returns **1**, replacing only the table collation. The INSERT remains unchanged because every quoted value is treated as harmless data.

   A quoted collation name is valid SQL: MariaDB’s grammar accepts `ident_or_text` after `COLLATE`. Consequently, preparation succeeds, the existing files and database are deleted, and this INSERT encounters the unsupported collation. This unsupported input must be rejected before deletion. [MariaDB grammar](https://github.com/MariaDB/server/blob/10.11/sql/sql_yacc.yy#L6308-L6314).

   A delimiter block is accepted as a trigger without verifying its contents. Both paths undermine the final RFaL/RFbv replies and the preservation guarantees in `pr.md:16–17,31`.
