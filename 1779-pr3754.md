<summary><strong>What changed in this PR</strong></summary>

This PR addresses #1779 by using Linux `MemAvailable` for server memory monitoring, so reclaimable page cache no longer causes inflated usage readings and unnecessary warnings.

**Changes:**
- Adds a shared memory utility with JVM fallback when `/proc/meminfo` is unavailable or incompatible.
- Uses the utility for monitoring snapshots and warning thresholds, leaving swap calculations unchanged.
- Adds eight tests covering memory parsing and fallback behavior.

[copilot-pull-request-reviewer] The 1% tolerance accepts genuine container limits just below the host total, such as 8,128 MiB versus 8,192 MiB, instead of using the JVM fallback. Both monitoring callers then combine host `MemAvailable` with the container's total, which can understate usage and suppress warnings. Reject differing totals and add a regression test with a container limit within 1% of the host total.
