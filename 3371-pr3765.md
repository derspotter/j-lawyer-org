<summary><strong>What changed in this PR</strong></summary>

Fixes an issue where confirming invoice type/number range changes in the client dialog could discard unsaved dialog edits by persisting changes before `updateInvoiceType()` triggers a server reload, and makes server-side history logging robust for invoices without a type.

**Changes:**
- Client: persist invoice + positions before assigning type/number range; abort confirmation if saving fails.
- Server: avoid `NullPointerException` when writing case history for invoices without `invoiceType`.
- Tests: add a regression test covering `updateInvoice()` and `updateInvoiceType()` for invoices without a type.

| j-lawyer-server/​j-lawyer-server-ejb/​src/​main/​java/​com/​jdimension/​jlawyer/​services/​ArchiveFileService.java | Makes case-history creation null-safe when an invoice has no type. |
| j-lawyer-client/​src/​main/​java/​com/​jdimension/​jlawyer/​client/​editors/​files/​InvoiceDialog.java | Saves pending dialog edits before changing invoice type/number range; `save()` now returns success. |
